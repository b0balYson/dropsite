# dropsite

[English](README.md) | **Русский** | [简体中文](README.zh-CN.md)

dropsite публикует сайты на вашем собственном сервере. Вы пишете ChatGPT или Claude «Сделай сайт кофейни и опубликуй», и через минуту сайт открывается по HTTPS-адресу на вашем домене. Правки, заявки с форм, посещаемость и пароль — такие же обычные просьбы в том же чате.

dropsite раздаёт готовые статические сайты (HTML, CSS, JavaScript, картинки). Сборку проектов и серверный код он не выполняет.

## Что понадобится

- **Арендованный сервер (VPS)** с Ubuntu 22.04, Ubuntu 24.04 или Debian 12 и памятью от 1 ГБ. Хостинг-провайдер присылает его IP-адрес и пароль root (или позволяет добавить SSH-ключ).
- **Домен**, на котором больше ничего нет, например `sites.example.com`.
- **ChatGPT или Claude**, чтобы делать сайты просьбами. Без чата сайты можно загружать в веб-интерфейсе.

## Установка одной командой

Выполните команду **на своём компьютере**, а не на сервере. На macOS и Linux откройте приложение «Терминал»; на Windows используйте WSL (Ubuntu из Microsoft Store) или Git Bash.

```bash
curl -fsSL https://raw.githubusercontent.com/b0balYson/dropsite/main/scripts/install-server.sh | sh
```

Установщик спросит IP сервера, пароль root (или файл ключа), короткое имя сервера, домен и почту — по-русски, по-английски или по-китайски, в зависимости от языка системы. Дальше он:

1. создаёт ключ только для этого сервера: пароль используется один раз и нигде не сохраняется;
2. ставит на сервер Docker и dropsite, открывает только порты 22, 80 и 443, включает ежедневный бэкап и запускает всё (10–20 минут);
3. добавляет сервер в `~/.ssh/config` на вашем компьютере: команда `ssh <имя>` подключается и открывает закрытый туннель к веб-интерфейсу;
4. говорит, какие DNS-записи создать там, где куплен домен: запись `A` для `@` и для `*` с IP сервера (и `AAAA`, если у сервера есть IPv6), и ждёт, пока домен заработает;
5. показывает логин администратора, сгенерированный пароль и как подключить ChatGPT или Claude.

Если что-то пошло не так, запустите ту же команду ещё раз: готовые шаги пропускаются. Подробности и параметры: [docs/install.md](docs/install.md#one-command-installer).

## Первые шаги

1. Выполните `ssh <имя>`, не закрывайте окно и откройте в браузере `http://localhost:<порт>` (порт установщик показывает в конце). Войдите с почтой и сгенерированным паролем.
2. Страница **«Начало работы»** — список шагов, который сам проверяет сервер: домен указывает сюда, HTTPS работает, чат подключён, первый сайт создан. Она показывает точные DNS-записи с кнопками копирования и что исправить, если шаг не прошёл. Необязательные шаги: пригласить коллегу и настроить Telegram или почту для заявок.
3. Откройте **«Подключить ИИ»**, выберите свой чат и пройдите пронумерованные шаги. Вы добавляете адрес `https://api.<ваш домен>/mcp` как коннектор, затем нажимаете **«Подключить»** и вводите одноразовый код подключения на открывшейся странице dropsite. Пароль в чате не запрашивается никогда.
4. Попросите чат: «Сделай сайт кофейни и опубликуй».

## Что умеет dropsite

### Сайты по просьбе

- **Публикация из чата.** ChatGPT, claude.ai, Claude Desktop и Claude Code делают сайт, публикуют его и присылают рабочую ссылку. Сайты самодостаточны (свои картинки и шрифты, без сторонних CDN), свёрстаны сначала для телефона и быстро загружаются.
- **Правка из любого нового чата.** Ассистент читает опубликованные файлы с сервера, меняет только то, что просили, и публикует новую версию.
- **Или без чата.** Перетащите zip или tar.gz на сайт в веб-интерфейсе, выполните `dropsite deploy ./папка` или вызовите HTTP API.
- **Покажите сайт, который нравится.** Дайте ссылку или картинку — получите оригинальный сайт в похожем стиле: палитра, шрифты, отступы, структура, но никогда не чужие тексты, картинки или логотип ([docs/references.md](docs/references.md)).
- **Шаблон — только если попросите.** Пять стартовых сайтов (кафе, услуги, мероприятие, портфолио, ссылки) на русском или английском; в остальных случаях ассистент придумывает дизайн каждого сайта заново ([docs/screenshots.md](docs/screenshots.md#templates)).
- **Копия сайта**, чтобы попробовать другой вариант, не трогая исходный.

### Безопасная публикация

- **Черновики с предпросмотром.** Сохраните новую версию черновиком и проверьте её по закрытому адресу предпросмотра; посетители видят текущую версию, пока вы не нажмёте **«Опубликовать»**. На уже работающем сайте ассистент делает черновик и спрашивает, публиковать ли.
- **Публикация по расписанию.** Подготовьте версию сейчас, и она выйдет в назначенное время, до года вперёд.
- **Версии и откат.** Каждая публикация — отдельная версия. Возврат к предыдущей мгновенный, и посетители никогда не видят наполовину обновлённый сайт.
- **Отчёт о качестве.** Каждая публикация получает оценку и список проблем: битые ссылки, отсутствующие файлы, файлы с чужих серверов, картинки без `alt`, страницы без заголовка или описания, самые тяжёлые страницы ([docs/quality.md](docs/quality.md)).
- **Автоматическая оптимизация.** WebP-копии картинок JPEG и PNG для браузеров, которые их понимают, а также `sitemap.xml`, `robots.txt` и favicon, если у сайта их нет. Ваши файлы не меняются ([docs/publishing.md](docs/publishing.md)).
- **Снимки экрана и сравнение «было | стало».** С необязательным рендерером ассистент смотрит на свою работу на компьютере и телефоне и сравнивает две версии ([docs/screenshots.md](docs/screenshots.md)).

### Заявки и живое содержимое

- **Формы без стороннего сервиса.** Заявки хранятся на вашем сервере и доставляются в Telegram, на почту или в подписанный HTTPS-вебхук, с повторами. Защита от ботов: скрытое поле-ловушка, ограничение частоты и необязательная self-hosted проверка Altcha. Заявки видны на экране сайта и выгружаются в CSV ([docs/forms.md](docs/forms.md)).
- **Данные сайта, которые правятся из чата.** Меню, цены, каталог, расписание или отзывы хранятся в коллекциях данных, которые загружают страницы. «Поменяй цену капучино на 250» действует сразу, без новой версии. Коллекция бывает публичной (пишет только владелец) или модерируемой (посетители предлагают записи, вы одобряете). Готовые шаблоны коллекций: меню, каталог, услуги, мероприятия, команда, вопросы и ответы, отзывы.
- **Google Таблицы.** Отправляйте заявки в таблицу или заполняйте коллекцию данных из неё — по кнопке или по расписанию ([docs/sheets.md](docs/sheets.md)).
- **Ключи API остаются в секрете.** Страница может обращаться к стороннему API (OpenAI, CRM, бот Telegram) через ваш сервер, который сам добавляет ключ. Ключ вставляется только в веб-интерфейсе; чат и API его не принимают и не показывают ([docs/proxy.md](docs/proxy.md)).

### Кто что видит

- **Сайты под паролем**, скрытые от поисковиков или с последним днём работы, после которого сайт закрывается ([docs/site-access.md](docs/site-access.md)).
- **Свои домены.** Сайт открывается на `promo.example.ru` в дополнение к адресу на базовом домене; ассистент подскажет, какие DNS-записи создать, а администратор подтверждает домен ([docs/external-domains.md](docs/external-domains.md)).
- **Общие пространства для команд.** Создайте пространство, добавьте коллег, и каждый участник управляет его сайтами. В остальном пользователь видит только свои сайты.
- **Статистика без скриптов.** Просмотры и посетители по дням, популярные страницы и источники — по журналу сервера. При желании добавьте счётчик Яндекс.Метрики или Google Analytics 4 по его номеру ([docs/statistics.md](docs/statistics.md)).

### Надёжная эксплуатация

- **Журнал действий.** Администратор видит входы, публикации, откаты, изменения пользователей, доменов, форм и настроек.
- **Три языка интерфейса:** русский, английский и упрощённый китайский.
- **Готовые образы и версионные релизы** для amd64 и arm64 с подписанным происхождением сборки; на сервере ничего не компилируется ([docs/releasing.md](docs/releasing.md)).
- **Бэкапы, обновление и откат одной командой:** ежедневный бэкап, `dropsite-update`, `dropsite-rollback`.
- **Сайты продолжают работать**, пока управляющий сервис остановлен или обновляется.

## Подробности

### Требования

- Linux-сервер, amd64 или arm64; Git, Docker Engine 24+ и Compose 2.24.4+ (установщик ставит их сам).
- Открытые порты 80 и 443 (TCP) и 443/UDP для HTTP/3. Порт веб-интерфейса 8082 должен быть закрыт из интернета.
- 2 vCPU и 4 ГБ RAM обслуживают до 10 000 сайтов и 1000 пользователей; для запуска готовых образов достаточно 1 ГБ RAM. Сборке из исходников на 1 CPU и 1 ГБ нужен swap 2 ГБ ([память при сборке](docs/install.md#build-memory)).
- Отдельный базовый домен. Опубликованные сайты выполняют произвольный JavaScript на его поддоменах: не размещайте на нём сервисы компании, формы входа и cookies. Для публичных инсталляций с недоверенными пользователями подайте домен в [Public Suffix List](https://publicsuffix.org/).

Как устроено: два контейнера. **Caddy** раздаёт сайты по имени хоста и получает HTTPS-сертификаты; его конфигурация статическая. **control** (один бинарник на Go) хранит базу, учётные записи, API, MCP-сервер и веб-интерфейс и публикует версию, атомарно переключая ссылку, которую читает Caddy.

### Варианты установки

**Установщик одной командой** (см. выше). Любой ответ можно передать параметром для автоматизации (`--host`, `--name`, `--domain`, `--email`, `--key`, `--yes`, …), а `--check-dns --name <имя>` проверяет DNS позже: [docs/install.md](docs/install.md#one-command-installer). Установщик входит как `root`; провайдеры, которые дают только пользователя с sudo, пока не поддерживаются.

**Вручную через Docker Compose.** Создайте DNS-записи `A`/`AAAA` для `example.site` и `*.example.site` с IP сервера (запись `*` покрывает и `api.example.site`), затем:

```bash
git clone https://github.com/b0balYson/dropsite.git
cd dropsite
# Тег последнего релиза: compose-файл и Caddyfile того же релиза, что и образы.
git checkout "$(git tag -l 'v*' --sort=-v:refname | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$' | head -n 1)"
cd deploy
cp .env.example .env
chmod 600 .env
# Заполните BASE_DOMAIN, ACME_EMAIL, ADMIN_EMAIL, ADMIN_PASSWORD
nano .env
docker compose config --quiet
docker compose pull
docker compose up -d --wait
docker compose ps
```

`control` должен быть `healthy`, `caddy` — `running`; при ошибке смотрите `docker compose logs --tail=100 control caddy`. Веб-интерфейс слушает только `127.0.0.1:8082`: открывайте его через `ssh -L 8082:127.0.0.1:8082 you@server`. Для команды привяжите его к адресу сервера в приватной overlay-сети (Tailscale, WireGuard, NetBird) через `ADMIN_BIND_IP` и `UI_URL`. Подробнее: [docs/install.md](docs/install.md), [docs/production-checklist.md](docs/production-checklist.md).

**Версии.** Каждый релиз — Git-тег `vX.Y.Z` с образами `ghcr.io/b0balyson/dropsite-control` и `ghcr.io/b0balyson/dropsite-caddy`. `DROPSITE_VERSION=latest` в `.env` (по умолчанию) следует за новыми релизами; укажите `X.Y.Z`, чтобы остаться на одном. Если релиза нет или нужно запустить свои изменения, соберите из исходников: `docker compose up -d --build --wait` ([сборка из исходников](docs/install.md#building-from-source), [docs/releasing.md](docs/releasing.md)).

**HTTPS-сертификаты.** По умолчанию (`TLS_MODE=ondemand`) каждый адрес получает свой сертификат Let's Encrypt при первом открытии. Let's Encrypt выдаёт не больше **50 новых сертификатов на зарегистрированный домен за 7 дней**; сайт со случайным и читаемым адресом расходует два, так что рассчитывайте примерно на **25 новых сайтов в неделю**. Адрес предпросмотра черновиков стоит ещё один сертификат, один раз. Продления не считаются. Если этого мало, переходите в **режим wildcard** (`TLS_MODE=wildcard`, `compose.wildcard.yml`): один сертификат на `*.<BASE_DOMAIN>` через DNS-01, новые сайты сертификатов не расходуют; нужны DNS в Cloudflare и API-токен с правом `Zone.DNS:Edit`, а у каждой версии появляется свой адрес предпросмотра. По шагам: [docs/tls.md](docs/tls.md). Все выпущенные сертификаты попадают в публичные журналы Certificate Transparency, поэтому адреса сайтов не секретны.

### Подключение ИИ-клиентов

| Клиент | Как |
| --- | --- |
| ChatGPT | Settings → Apps → Advanced settings → Developer mode, затем создайте приложение с адресом `https://api.<BASE_DOMAIN>/mcp` и OAuth. Собственные приложения доступны не на всех тарифах; проверьте на [help.openai.com](https://help.openai.com/). |
| claude.ai, Claude Desktop | Settings → Connectors → Add custom connector, вставьте адрес, нажмите Connect. |
| Claude Code | `claude mcp add --transport http dropsite https://api.<BASE_DOMAIN>/mcp`, затем `/mcp` для входа. |
| Claude Code, Codex, Cursor, Claude Desktop на компьютере | **«Подключить»** на странице «Подключить ИИ» показывает команду в одну строку: она ставит CLI, входит и запускает `dropsite setup` (скилл публикации или локальный MCP-сервер для Claude Desktop). |

Код подключения действует 10 минут и срабатывает один раз. Через чат даже администратор управляет только своими сайтами; настройки установки остаются в веб-интерфейсе, а токены и коды подключения чат не создаёт. Подключённые приложения видны и отключаются на странице «Подключить ИИ». Инструменты, правила и ограничения: [docs/ai-clients.md](docs/ai-clients.md), [docs/mcp-tools.md](docs/mcp-tools.md).

### CLI

Установщики скачивают бинарник из GitHub Releases и проверяют его SHA-256 (`DROPSITE_VERSION=X.Y.Z` выбирает релиз):

```bash
curl -fsSL https://raw.githubusercontent.com/b0balYson/dropsite/main/scripts/install.sh | DROPSITE_SERVER=https://api.example.com DROPSITE_CODE=ABCD-EFGH-JKMNP sh
```

```powershell
$env:DROPSITE_SERVER='https://api.example.com'; $env:DROPSITE_CODE='ABCD-EFGH-JKMNP'; irm https://raw.githubusercontent.com/b0balYson/dropsite/main/scripts/install.ps1 | iex
```

Команды: `login`, `setup` (`--remove` отменяет), `deploy` (`--draft`, `--expires 7d`), `sites`, `deploys`, `rollback`, `draft publish|discard`, `clone`, `domains`, `workspaces`, `delete`, `mcp`, `version`. Первый `dropsite deploy ./dist` создаёт сайт и запоминает его в `.dropsite.json`, следующие обновляют тот же сайт. Каталог с похожими на секреты файлами (`.env*`, ключи) не публикуется без `--skip-sensitive` или `--include-sensitive`. CLI подсказывает, если его версия и версия сервера расходятся на минорную или больше. Если релиза нет, [соберите CLI из исходников](docs/install.md#cli-from-source).

### HTTP API

`https://api.<BASE_DOMAIN>/api/v1` с Bearer-токеном, созданным в веб-интерфейсе; описание OpenAPI — по адресу `/api/v1/openapi.json`. Контракт: [docs/api-contract.md](docs/api-contract.md).

В архиве сайта нужен `index.html` в корне (единственная папка верхнего уровня вроде `dist/` разворачивается); по умолчанию до 50 МБ в распакованном виде, 20 МБ на файл, 2000 файлов. `/about` отдаёт `about.html`, `404.html` — страница «не найдено», `200.html` включает режим одностраничного приложения. `/_form/` и `/_dropsite/` принадлежат платформе.

### Настройки

Настройки хранятся в `deploy/.env` ([.env.example](deploy/.env.example)).

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BASE_DOMAIN` | обязательна | Базовый домен сайтов |
| `ACME_EMAIL` | обязательна | Почта аккаунта для сертификатов |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | обязательны | Первый администратор; пароль читается только при первом запуске |
| `DROPSITE_VERSION` | `latest` | Какие образы релиза запускать, или `X.Y.Z` |
| `ADMIN_BIND_IP`, `UI_URL` | `127.0.0.1`, `http://<ADMIN_BIND_IP>:8082` | Где слушает веб-интерфейс и какой адрес попадает в приглашения |
| `API_HOST` | `api.<BASE_DOMAIN>` | Хост API и MCP |
| `TLS_MODE`, `CF_API_TOKEN` | `ondemand` | Режим сертификатов; токен только для wildcard |
| `MAX_SITE_BYTES`, `MAX_FILE_BYTES`, `MAX_FILES`, `MAX_SITES_PER_USER`, `KEEP_RELEASES` | 50 МБ, 20 МБ, 2000, 10, 5 | Лимиты; администратор переопределяет их в «Настройках» и для каждого пользователя |
| `MAX_DOMAINS_PER_SITE` | `5` | Своих доменов на сайт |
| `SERVER_IPS` | адреса `BASE_DOMAIN` | Публичные IP, которые показываются как цель DNS |
| `PUBLISH_OPTIMIZE` | `on` | Оптимизация при публикации |
| `COMPOSE_PROFILES`, `RENDERER_URL` | выключено | Необязательный рендерер снимков ([docs/screenshots.md](docs/screenshots.md)) |

Ещё переменные: `RESERVED_SLUGS` (дополнительные запрещённые короткие адреса), `LOG_LEVEL`, `STATS_INTERVAL` и `STATS_LOG_FILE` (`off` выключает статистику), `TELEGRAM_API_URL`, `FORM_WEBHOOK_ALLOW_CIDRS` (только для тестовых стендов). Бот Telegram, почтовый сервер, сервисный аккаунт Google и лимиты администратор задаёт в разделе **«Настройки»** веб-интерфейса.

### Эксплуатация

| Задача | Сервер от установщика | Вручную, из `dropsite/deploy` |
| --- | --- | --- |
| Обновить | `ssh <имя> dropsite-update` | бэкап, переход на новый тег, `docker compose pull && docker compose up -d --wait` |
| Отменить последнее обновление | `ssh <имя> dropsite-rollback` | прежний тег и бэкап, сделанный перед обновлением |
| Бэкап | ежедневно автоматически или `ssh <имя> dropsite-backup` | `docker compose exec -T control /control backup - > backup.tar.gz` |
| Сбросить пароль администратора | `ssh <имя> dropsite-admin-password` | `docker compose exec -T control /control reset-password [email]` |
| Логи | `docker compose logs -f` | так же |

Миграции применяются автоматически; откат схемы не поддерживается, поэтому откатывайтесь вместе с бэкапом. Ключ секретов форм `state/secrets.key` в бэкап не входит: храните его копию. Никогда не выполняйте `docker compose down -v` — это удаляет данные. Подробности: [docs/backup.md](docs/backup.md), [docs/releasing.md](docs/releasing.md#on-a-server).

### Безопасность

- Веб-интерфейс работает на отдельном listener-е, недоступном из интернета; пароли вводятся только там.
- Чат-клиенты подключаются по OAuth 2.1 (PKCE, короткоживущие токены, ротация refresh-токенов) с подтверждением одноразовым кодом. API принимает только Bearer-токены, которые хранятся в виде хэшей.
- Чужой сайт всегда отвечает «не найдено». Архив проверяется до записи на диск, а публикации с секретными ключами в файлах отклоняются.
- Caddy читает сайты только на чтение и не имеет доступа к базе. Оба контейнера работают не от root с корневой файловой системой только для чтения.
- Используйте отдельный базовый домен (см. «Требования»).
- Интерфейс администратора не запустится на публичном адресе без явного разрешения; пароль первого администратора после установки на сервере не хранится.
- Модель угроз, настройка CDN и реакция на злоупотребления: [docs/security.md](docs/security.md).
