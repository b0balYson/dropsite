# dropsite

[English version](README.md)

Self-hosted публикация статических сайтов. Маркетолог пишет в ChatGPT или Claude «Сделай сайт кофейни и опубликуй» или перетаскивает zip в веб-интерфейс и через несколько секунд получает HTTPS-ссылку на поддомене вашего домена; правки, посещаемость, заявки и пароль — такие же обычные просьбы в том же чате. Без отдельного VPS, git и DevOps.

- Один сервер. Сборка из исходников и запуск: `docker compose up -d --build --wait`.
- На входе архив, на выходе HTTPS-ссылка. Каждый сайт получает случайный адрес вида `k3f9x2m7qa.example.site` и по желанию читаемый, например `promo-may.example.site`.
- Каждая публикация — неизменяемый релиз: переключение и откат мгновенные, без единого неудачного запроса.
- Пользователь видит и меняет только свои сайты. Администратор управляет пользователями, всеми сайтами, лимитами и журналом.
- Управление сайтами из чата (ChatGPT, claude.ai, Claude Desktop, Claude Code), подключённого один раз, а также из веб-интерфейса, CLI `dropsite` и HTTP API.
- Сайты продолжают работать, пока управляющий сервис остановлен или обновляется.

dropsite раздаёт только готовую статику (HTML, CSS, JS, картинки). Сборку проектов и серверный код он не выполняет.

## Как устроено

Два контейнера. **Caddy** раздаёт файлы по имени хоста и выпускает TLS-сертификаты по требованию; его конфигурация статическая и никогда не перезагружается. **control** (один бинарник на Go) хранит базу, учётные записи, API и веб-интерфейс и публикует релизы, атомарно переключая симлинки на общем томе, который читает Caddy.

## Установка из репозитория

Нужно: Linux-сервер (amd64 или arm64), Git, Docker Engine 24+ и Compose 2.24.4+, открытые порты 80 и 443, домен. На сервере с 1 CPU и 1 ГБ RAM рекомендуем добавить 2 ГБ swap (подкачки на диск) для сборки; диагностика — в [docs/install.md](docs/install.md#build-memory). Go устанавливать на сервер не нужно: Docker скачивает инструменты и собирает приложение внутри контейнера. Нужен доступ к интернету для базовых образов и зависимостей. Первая сборка может занять несколько минут.

### 1. Выберите отдельный базовый домен

Используйте домен (или поддомен вида `sites.example.com`), на котором **больше ничего нет**. Опубликованные сайты выполняют произвольный JavaScript на его поддоменах, поэтому на базовом домене не должно быть сервисов компании, форм входа и cookies, и он не должен делить с ними cookies. Для публичных инсталляций с недоверенными пользователями подайте домен в [Public Suffix List](https://publicsuffix.org/), чтобы браузеры изолировали сайты друг от друга.

### 2. Направьте DNS на сервер

| Запись | Имя | Значение |
| --- | --- | --- |
| A (и AAAA, если есть IPv6) | `example.site` | IP сервера |
| A (и AAAA) | `*.example.site` | IP сервера |

Запись `*` покрывает и `api.example.site`, если отдельная запись для `api` не перекрывает её. Если используете Cloudflare, домен должен иметь статус **Active**, а у регистратора должны быть указаны NS-серверы Cloudflare.

Проверьте `dig +short example.site` и `dig +short api.example.site`: оба имени должны возвращать IP сервера. `NXDOMAIN` означает, что DNS-записи нет. Пока DNS не работает, Caddy не выпустит сертификат, а ChatGPT не сможет определить настройки OAuth. В Cloudflare на время настройки используйте **DNS only**.

### 3. Настройте и запустите

```bash
git clone https://github.com/b0balYson/dropsite.git
cd dropsite/deploy
cp .env.example .env
chmod 600 .env
# Заполните BASE_DOMAIN, ACME_EMAIL, ADMIN_EMAIL, ADMIN_PASSWORD
nano .env
docker compose config --quiet
docker compose up -d --build --wait
docker compose ps
```

Выполняйте команды `docker compose` из каталога `dropsite/deploy`. Docker собирает `control` из этого репозитория. Готовые образы dropsite не нужны. Сохраняйте весь репозиторий: он нужен для следующих сборок. В `docker compose ps` сервис `control` должен иметь статус `healthy`, а `caddy` — `running`. Если запуск завершился ошибкой, выполните `docker compose logs --tail=100 control caddy`.

### 4. Откройте веб-интерфейс

Интерфейс слушает `ADMIN_BIND_IP:8082`, по умолчанию `127.0.0.1:8082`, и **никогда не публикуется в интернет**. Откройте его через SSH-туннель:

```bash
ssh -L 8082:127.0.0.1:8082 you@server
# затем откройте http://127.0.0.1:8082 и войдите с ADMIN_EMAIL / ADMIN_PASSWORD
```

Для команды задайте `ADMIN_BIND_IP` равным адресу сервера в приватной overlay-сети (Tailscale, WireGuard, NetBird) и `UI_URL` — адресу, который открывают сотрудники, например `http://100.64.0.10:8082`. Интерфейс работает по HTTP и должен оставаться в приватной сети.

Дальше: **Пользователи → создать**, отправьте сотруднику ссылку-приглашение (действует 72 часа); он задаёт пароль и публикует.

## Сайты из чата

Основной способ работы с dropsite — чат. Подключите его один раз к ChatGPT, claude.ai, Claude Desktop или Claude Code и просите обычными словами: ассистент сделает или изменит сайт, опубликует его и пришлёт рабочую ссылку. Знать форматы файлов, команды и устройство сервера не нужно.

1. **Подключите один раз.** На странице **Подключить ИИ** веб-интерфейса скопируйте адрес `https://api.<BASE_DOMAIN>/mcp` и выполните короткие шаги для своего чата (ChatGPT: режим разработчика → создать приложение; claude.ai и Claude Desktop: Settings → Connectors → Add custom connector; Claude Code: `claude mcp add --transport http dropsite <адрес>`). Когда откроется страница dropsite, нажмите **Подключить** на странице «Подключить ИИ» и введите одноразовый код; пароль не запрашивается никогда.
2. **Просите.** Например:

| Русский | English |
| --- | --- |
| «Сделай сайт кофейни и опубликуй» | "Make a coffee shop site and publish it" |
| «Измени фотографии и цены на моём сайте» | "Change the photos and prices on my site" |
| «Покажи посещаемость за неделю» | "Show visits for the week" |
| «Покажи последние заявки» | "Show the latest requests" |
| «Присылай заявки в Telegram» | "Send requests to Telegram" |
| «Закрой сайт паролем» | "Close the site with a password" |
| «Верни предыдущую версию» | "Bring back the previous version" |
| Администратор: «Поставь эту заглушку на корневой домен» | Administrator: "Put this placeholder on the root domain" |

Изменить сайт можно и из нового чата: ассистент читает текущие файлы сайта с сервера, меняет то, что просили, и публикует новую версию (предыдущая остаётся для отката). Сайты, которые он делает, несут свои картинки и шрифты с собой (без CDN и чужих ссылок на фото), свёрстаны сначала для телефона и быстро загружаются. Перед удалением или заменой чего-либо ассистент спрашивает подтверждение.

Что остаётся за людьми:

- первое подключение чата (страница «Подключить ИИ»);
- записи DNS своего домена: пользователь создаёт их у регистратора по значениям, которые назовёт ассистент, а администратор подтверждает домен;
- подтверждение канала доставки заявок: нажать Start в Telegram или прочитать код из письма;
- настройки установки (бот Telegram, почтовый сервер, пользователи, лимиты) задаёт администратор в веб-интерфейсе. Через чат даже администратор управляет только своими сайтами; единственное действие уровня установки — корневой домен.

Как ассистент узнаёт правила (инструкции сервера, инструмент `get_guide`, описания инструментов) и что поддерживает каждый чат: [docs/ai-clients.md](docs/ai-clients.md).

## Публикация

- **Чат (основной путь):** см. [Сайты из чата](#сайты-из-чата). Один вызов инструментов чата несёт до 16 МБ; большие сайты загружаются сессией, которая завершается одним релизом.
- **Веб-интерфейс:** создайте сайт и перетащите на него zip или tar.gz.
- **ИИ-ассистенты на компьютере (одна команда, по желанию):** на странице **Подключить ИИ** нажмите **Подключить**. Появится одноразовый код (10 минут) внутри готовой команды для macOS/Linux и для Windows. Команда ставит CLI, входит по коду и запускает `dropsite setup`, который подключает найденных ассистентов: скилл публикации для **Claude Code**, **Codex** и **Cursor** и локальный MCP-сервер для **Claude Desktop** с теми же инструментами, что и у коннектора. После этого скажите «опубликуй этот сайт».
- **Подробнее о коннекторе чата:** адрес коннектора — `https://api.<BASE_DOMAIN>/mcp`. Когда откроется страница dropsite, введите код подключения со страницы **Подключить ИИ**; пароль не запрашивается никогда. Собственные MCP-коннекторы в ChatGPT требуют режима разработчика и доступны не на всех тарифах; актуальные условия — на [help.openai.com](https://help.openai.com/). Подключённые приложения видны на странице **Подключить ИИ**, там же их можно отключить. Подробности: [docs/ai-clients.md](docs/ai-clients.md).
- **Управление кабинетом из чата:** кроме публикации, подключённый чат умеет переименовывать сайты и менять их адреса, ставить пароль, скрывать сайт от поисковиков или задавать последний день работы, подключать свои домены (и объясняет, какие DNS-записи создать), показывать статистику посещений, настраивать счётчики аналитики и показывать или отключать подключённые приложения; администратор также может поставить сайт на корень домена. Разрушающие действия требуют подтверждения, а токены и коды подключения чат не создаёт никогда. Список инструментов: [docs/ai-clients.md](docs/ai-clients.md#chats-chatgpt-claudeai-claude-desktop-claude-code).
- **Правка сайта из чата:** в любом новом чате скажите «поменяй цены на сайте кофейни»: ассистент прочитает опубликованные файлы, изменит только нужное и опубликует новую версию (прежняя остаётся для отката). Сайты больше 16 МБ передаются частями, а картинки и шрифты по ссылкам сервер скачивает сам, чтобы они лежали на сайте. Подробности: [docs/ai-clients.md](docs/ai-clients.md#changing-a-site-from-a-new-chat).
- **CLI вручную:** `dropsite login --server https://api.<BASE_DOMAIN> --code <код>` (или `--token` с ключом из свёрнутого раздела «Ручные ключи доступа»), затем `dropsite deploy ./dist`. Первый запуск создаёт сайт и запоминает его в `.dropsite.json`, следующие обновляют тот же сайт. Каталог с похожими на секреты файлами (`.env*`, ключи, учётные данные) не публикуется, команда перечисляет их; `--skip-sensitive` исключает их, `--include-sensitive` публикует вместе с ними.
- **HTTP API и MCP:** `https://api.<BASE_DOMAIN>/api/v1` с Bearer-токеном ([docs/api-contract.md](docs/api-contract.md), `/api/v1/openapi.json`); MCP-эндпоинт `https://api.<BASE_DOMAIN>/mcp` принимает те же API-токены или токены OAuth.

Команда выглядит так (страница подставляет сервер и код):

```bash
curl -fsSL https://raw.githubusercontent.com/b0balYson/dropsite/main/scripts/install.sh | DROPSITE_SERVER=https://api.example.com DROPSITE_CODE=ABCD-EFGH-JKMNP sh
```

```powershell
$env:DROPSITE_SERVER='https://api.example.com'; $env:DROPSITE_CODE='ABCD-EFGH-JKMNP'; irm https://raw.githubusercontent.com/b0balYson/dropsite/main/scripts/install.ps1 | iex
```

Без `--server` и `--code` установщики только ставят CLI. `dropsite setup --remove` убирает интеграции.

Установщики CLI скачивают бинарник из GitHub Releases. Если релиза ещё нет, соберите CLI из исходников на своём компьютере: [инструкция](docs/install.md#cli-from-source). Для запуска сервера и публикации через веб-интерфейс CLI не нужен.

### Свои домены

Сайт можно открыть и на домене владельца, например `promo.example.ru`: добавьте его в блоке **Свои домены** на экране сайта, командой `dropsite domains add <сайт> <домен>` или через `POST /sites/{id}/hostnames`. Направьте домен на сервер (CNAME на случайный адрес сайта или записи A/AAAA для корня домена). Сертификат и раздачу домен получает только после подтверждения администратором на экране **Внешние домены**, поэтому никто не может заставить сервер запрашивать сертификаты на произвольные имена. Подробности: [docs/external-domains.md](docs/external-domains.md).

### Что может быть в архиве сайта

`index.html` в корне (единственная папка верхнего уровня вроде `dist/` разворачивается автоматически). По умолчанию до 50 МБ в распакованном виде, до 20 МБ на файл, до 2000 файлов. Симлинки, абсолютные пути и `..` отклоняются. `.git`, `node_modules`, `__MACOSX`, `.DS_Store`, `Thumbs.db` пропускаются.

### Правила раздачи

| Поведение | Правило |
| --- | --- |
| Индекс | `/` и `/dir/` отдают `index.html`; `/dir` перенаправляет на `/dir/` |
| Чистые URL | `/about` отдаёт `about.html` |
| Своя 404 | `404.html` в корне отдаётся со статусом 404 |
| SPA | `200.html` в корне отдаётся со статусом 200 на любой ненайденный путь |
| Скрытые файлы | любой сегмент пути с точкой в начале — 404, кроме `/.well-known/` |
| Зарезервировано | `/_form/` и `/_dropsite/` принадлежат платформе (`/_dropsite/login` — страница пароля закрытых сайтов, `/_dropsite/data/` — данные сайта) |
| Кэш | HTML — `no-cache`, остальное — `public, max-age=3600` |

### Доступ: поисковики, пароль, срок жизни

Блок **«Доступ»** на экране сайта (и `PATCH /api/v1/sites/{ref}`) определяет, кто видит сайт и как долго. Изменения действуют сразу, без перезапусков.

- **Не показывать в поиске** (`noindex`): все ответы сайта, включая ошибки, получают `X-Robots-Tag: noindex, nofollow`.
- **Пароль** (`protected`): посетитель видит нейтральную страницу входа с названием сайта, вводит пароль, и вход на этом адресе запоминается на 7 дней. Смена пароля или снятие защиты выводит всех посетителей. Пароль хранится хэшем argon2id. Каждый вход дополнительно проходит self-hosted proof-of-work Altcha, который страница решает сама (около секунды на компьютере) и который резко усложняется после неудачных попыток; неверные пароли ограничены: 10 за 15 минут с одного IP, а волна неудач на одном сайте усложняет проверку для всех вместо блокировки входа. Подробности: [docs/site-access.md](docs/site-access.md). Открытые сайты к `control` не обращаются; закрытые проверяются на каждом запросе, а пока `control` недоступен, вместо содержимого показывается страница «временно недоступен».
- **Срок жизни** (`expires_at`, в CLI `--expires 7d`): после последнего дня сайт перестаёт открываться в течение минуты и удаляется через 7 дней, как удалённый. Интерфейс предупреждает за 3 дня.

Подробнее: [docs/site-access.md](docs/site-access.md).
## Формы и заявки

Любой опубликованный сайт принимает заявки с форм без стороннего сервиса: укажите в форме адрес `/_form/<имя>` того же сайта.

```html
<form action="/_form/lead" method="post">
  <input name="name" required> <input name="phone" type="tel" required>
  <input name="_hp" tabindex="-1" autocomplete="off" aria-hidden="true" style="position:absolute;left:-10000px">
  <input type="hidden" name="_next" value="/thanks.html">
  <altcha-widget challenge="/_form/challenge"></altcha-widget>
  <button>Отправить</button>
</form>
<script async defer src="/_dropsite/altcha.js" type="module"></script>
```

Каждая заявка сначала сохраняется, затем в фоне с повторами доставляется в каналы, которые владелец добавляет на экране сайта: чат Telegram (один бот на инсталляцию, токен задаёт администратор), адрес почты (SMTP задаёт администратор) или HTTPS-вебхук с подписью HMAC-SHA256. Защита от спама: honeypot-поле `_hp`, необязательная проверка времени заполнения, ограничение частоты по IP и по сайту, лимит тела 64 КБ и, если владелец включит, self-hosted [Altcha](https://altcha.org) — proof-of-work, сложность которого растёт при повторах с одного IP. Заявки хранятся 90 дней (настраивается), видны на экране сайта и выгружаются в CSV. Секреты (токен бота, пароль SMTP, секреты вебхуков) хранятся зашифрованными ключом `state/secrets.key`. Подробности: [docs/forms.md](docs/forms.md).

### Ключи API для страниц

Страница может вызвать сторонний API с ключом (OpenAI, CRM, бот Telegram) через `/_dropsite/proxy/<имя>/<путь>` на своём адресе: сервер добавляет ключ и пересылает запрос, ключ на страницу не попадает. Владелец вставляет ключ на экране сайта **Ключи API**; API и чат ключ не принимают и не показывают. Действуют списки хостов, методов и путей, ограничения размера и частоты, запрет частных сетей; на закрытом сайте прокси доступен только после входа. Подробности: [docs/proxy.md](docs/proxy.md).

Из ChatGPT или claude.ai владелец делает то же самое обычными фразами («покажи последние заявки», «присылай заявки в Telegram», «выгрузи заявки за неделю»): у MCP-серверов (удалённого и локального `dropsite mcp` для Claude Desktop) есть инструменты для настроек форм, заявок с фильтрами, ограниченной выгрузки CSV и каналов доставки; коды подтверждения и ссылку на Telegram-бота пользователь по-прежнему получает сам.

## Данные сайта

Сайт может хранить небольшие данные в коллекциях JSON-документов (меню с ценами, каталог, расписание, отзывы), а страницы загружают их через `fetch('/_dropsite/data/<имя>')`. Владелец меняет документы из чата («поменяй цену капучино на 250»), в кабинете (экран сайта, раздел «Данные») или через API, и изменение сразу видно на сайте: новый релиз не нужен, откат релиза данные не трогает. Коллекцию в режиме `public` пишет только владелец; коллекция `moderated` принимает предложения посетителей через `POST /_dropsite/data/<имя>` (JSON проверяется по JSON Schema коллекции, защита та же, что у форм: Origin, ограничение частоты, honeypot, Altcha по флагу сайта), а показываются только одобренные владельцем документы. На закрытом паролем сайте данные отдаются только после входа. Ограничения: 20 коллекций на сайт, 5000 документов в коллекции, 16 КБ на документ. Код на сервере не исполняется: страницы сами отрисовывают данные и оставляют свой HTML как запасное содержимое, если данные недоступны.

## Статистика посещений и счётчики аналитики

На экране сайта видны просмотры страниц по дням за 30 дней, итоги, популярные страницы и источники переходов; администратор в «Все сайты» видит ещё и просмотры за 7 дней. Числа берутся из access-лога Caddy, поэтому скрипты на сайтах не нужны: роботы и запросы к картинкам, стилям и скриптам не учитываются, а посетитель определяется по IP-адресу и браузеру в пределах суток UTC, при этом ни то ни другое не хранится. Те же данные отдаёт `GET /api/v1/sites/{ref}/stats?days=30`.

Владелец сайта может указать номер счётчика Яндекс.Метрики и/или Measurement ID GA4 (администратор — ещё и общие для всех сайтов). dropsite вставит стандартный код счётчика перед `</head>` во все HTML-страницы каждого нового релиза; смена ID сайта создаёт новый релиз с обновлённым кодом. Принимаются только идентификаторы, не HTML. Подробности: [docs/statistics.md](docs/statistics.md).

## Сертификаты и лимиты Let's Encrypt

По умолчанию каждый адрес получает свой сертификат при первом обращении (`TLS_MODE=ondemand`). Caddy запрашивает сертификат только для существующих адресов.

Let's Encrypt выдаёт **50 новых сертификатов на зарегистрированный домен за 7 дней** (на август 2026, см. [rate limits](https://letsencrypt.org/docs/rate-limits/)). Сайт со slug расходует два сертификата (случайный адрес и slug), то есть рассчитывайте примерно на **25 новых сайтов в неделю**. Продления в лимит не входят. При отказе Let's Encrypt Caddy переключается на ZeroSSL. Если этого мало, переходите в режим wildcard.

Каждый выпущенный сертификат попадает в публичные журналы Certificate Transparency, поэтому адреса сайтов не секретны.

**Режим wildcard** (`TLS_MODE=wildcard`) использует один сертификат на `*.<BASE_DOMAIN>` и корень, полученный через проверку DNS-01, поэтому новые сайты сертификатов не расходуют. Нужны DNS в Cloudflare (других провайдеров можно добавить) и API-токен с правом `Zone.DNS:Edit`:

```sh
# .env: CF_API_TOKEN=<токен>
docker compose -f docker-compose.yml -f compose.wildcard.yml up -d --build --wait
```

В этом режиме у каждого релиза есть ещё и свой превью-адрес `https://p-<релиз>-<сайт>.<BASE_DOMAIN>/` (поисковики его не индексируют), он показан в истории релизов. Переход по шагам и откат: [docs/tls.md](docs/tls.md).

## Эксплуатация

- **Бэкап:** `docker compose exec -T control /control backup - > backup-$(date +%F).tar.gz`. Восстановление — в [docs/backup.md](docs/backup.md).
- **Обновление:** из `dropsite/deploy` сделайте бэкап, выполните `git pull --ff-only`, затем `docker compose up -d --build --wait`. Настройки в `.env` и данные в Docker-томах сохраняются. Миграции применяются автоматически, откат схемы не поддерживается. Порядок действий — в [docs/backup.md](docs/backup.md#upgrade).
- **Логи:** JSON в stdout обоих контейнеров: `docker compose logs -f`. Кроме того, Caddy пишет access-лог сайтов на том `logs` для статистики (ротация по 50 МБ, хранятся 5 старых файлов).
- **Здоровье:** `docker compose ps` показывает проверку здоровья `control`.

Подробнее: [docs/install.md](docs/install.md), [docs/backup.md](docs/backup.md), [docs/tls.md](docs/tls.md), [docs/external-domains.md](docs/external-domains.md), [docs/production-checklist.md](docs/production-checklist.md), [docs/statistics.md](docs/statistics.md), [docs/forms.md](docs/forms.md).

## Модель безопасности

- Веб-интерфейс работает на отдельном listener-е, недоступном из интернета; cookie сессии привязана только к хосту интерфейса.
- API принимает только Bearer-токены, cookies не принимаются. Токен показывается один раз, хранится в виде хэша, может истекать и отзываться.
- Чужой сайт всегда отвечает «не найдено».
- Пароль вводится только во внутреннем интерфейсе. Чат-клиенты авторизуются на публичном API-хосте по OAuth 2.1 (PKCE, короткие access-токены, ротация refresh-токенов с обнаружением повторного использования); пользователь подтверждает доступ одноразовым кодом подключения из интерфейса, а не паролем.
- Архив проверяется до записи на диск: никаких выходов за пределы каталога, ссылок, устройств и zip-бомб.
- Caddy видит том сайтов только на чтение и не имеет доступа к базе и токенам. Оба контейнера работают не от root с корневой файловой системой только для чтения.
