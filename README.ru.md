# dropsite

[English version](README.md)

Self-hosted публикация статических сайтов. Маркетолог собирает лендинг с ИИ-ассистентом, говорит «опубликуй» или перетаскивает zip в веб-интерфейс и через несколько секунд получает HTTPS-ссылку на поддомене вашего домена. Без отдельного VPS, git и DevOps.

- Один сервер, одна команда: `docker compose up -d`.
- На входе архив, на выходе HTTPS-ссылка. Каждый сайт получает случайный адрес вида `k3f9x2m7qa.example.site` и по желанию читаемый, например `promo-may.example.site`.
- Каждая публикация — неизменяемый релиз: переключение и откат мгновенные, без единого неудачного запроса.
- Пользователь видит и меняет только свои сайты. Администратор управляет пользователями, всеми сайтами, лимитами и журналом.
- Публикация из веб-интерфейса, CLI `dropsite`, HTTP API или ИИ-ассистента (Claude Code, Codex) через CLI.
- Сайты продолжают работать, пока управляющий сервис остановлен или обновляется.

dropsite раздаёт только готовую статику (HTML, CSS, JS, картинки). Сборку проектов и серверный код он не выполняет.

## Как устроено

Два контейнера. **Caddy** раздаёт файлы по имени хоста и выпускает TLS-сертификаты по требованию; его конфигурация статическая и никогда не перезагружается. **control** (один бинарник на Go) хранит базу, учётные записи, API и веб-интерфейс и публикует релизы, атомарно переключая симлинки на общем томе, который читает Caddy.

## Установка за 5 минут

Нужно: Linux-сервер с Docker и плагином Compose, открытые порты 80 и 443, домен.

### 1. Выберите отдельный базовый домен

Используйте домен (или поддомен вида `sites.example.com`), на котором **больше ничего нет**. Опубликованные сайты выполняют произвольный JavaScript на его поддоменах, поэтому на базовом домене не должно быть сервисов компании, форм входа и cookies, и он не должен делить с ними cookies. Для публичных инсталляций с недоверенными пользователями подайте домен в [Public Suffix List](https://publicsuffix.org/), чтобы браузеры изолировали сайты друг от друга.

### 2. Направьте DNS на сервер

| Запись | Имя | Значение |
| --- | --- | --- |
| A (и AAAA, если есть IPv6) | `example.site` | IP сервера |
| A (и AAAA) | `*.example.site` | IP сервера |

### 3. Настройте и запустите

```bash
mkdir dropsite && cd dropsite
base=https://raw.githubusercontent.com/b0balYson/dropsite/main/deploy
curl -fsSLO "$base/docker-compose.yml" -fsSLO "$base/Caddyfile"
curl -fsSL "$base/.env.example" -o .env
# Заполните BASE_DOMAIN, ACME_EMAIL, ADMIN_EMAIL, ADMIN_PASSWORD
nano .env
docker compose up -d
```

### 4. Откройте веб-интерфейс

Интерфейс слушает `ADMIN_BIND_IP:8082`, по умолчанию `127.0.0.1:8082`, и **никогда не публикуется в интернет**. Откройте его через SSH-туннель:

```bash
ssh -L 8082:127.0.0.1:8082 you@server
# затем откройте http://127.0.0.1:8082 и войдите с ADMIN_EMAIL / ADMIN_PASSWORD
```

Для команды задайте `ADMIN_BIND_IP` равным адресу сервера в приватной overlay-сети (Tailscale, WireGuard, NetBird) и `UI_URL` — адресу, который открывают сотрудники, например `http://100.64.0.10:8082`. Интерфейс работает по HTTP и должен оставаться в приватной сети.

Дальше: **Пользователи → создать**, отправьте сотруднику ссылку-приглашение (действует 72 часа); он задаёт пароль и публикует.

## Публикация

- **Веб-интерфейс:** создайте сайт и перетащите на него zip или tar.gz.
- **CLI:** на странице **Подключить ИИ** выпустите токен и выполните показанную команду `dropsite login`, затем `dropsite deploy ./dist`. Первый запуск создаёт сайт и запоминает его в `.dropsite.json`, следующие обновляют тот же сайт.
- **ИИ-ассистенты:** на странице **Подключить ИИ** есть готовые инструкции для Claude Code (`skills/claude-code/SKILL.md`) и Codex (`skills/codex/AGENTS.md`). Ассистент публикует через CLI.
- **HTTP API:** `https://api.<BASE_DOMAIN>/api/v1`, Bearer-токен, см. [docs/api-contract.md](docs/api-contract.md) и `/api/v1/openapi.json`.

Установка CLI (Linux, macOS):

```bash
curl -fsSL https://raw.githubusercontent.com/b0balYson/dropsite/main/scripts/install.sh | sh
```

Windows (PowerShell):

```powershell
irm https://raw.githubusercontent.com/b0balYson/dropsite/main/scripts/install.ps1 | iex
```

### Что может быть в архиве сайта

`index.html` в корне (единственная папка верхнего уровня вроде `dist/` разворачивается автоматически). По умолчанию до 50 МБ в распакованном виде, до 20 МБ на файл, до 2000 файлов. Симлинки, абсолютные пути и `..` отклоняются. `.git`, `node_modules`, `__MACOSX`, `.DS_Store`, `Thumbs.db` пропускаются.

### Правила раздачи

| Поведение | Правило |
| --- | --- |
| Индекс | `/` и `/dir/` отдают `index.html`; `/dir` перенаправляет на `/dir/` |
| Чистые URL | `/about` отдаёт `about.html` |
| Своя 404 | `404.html` в корне отдаётся со статусом 404 |
| SPA | `200.html` в корне отдаётся со статусом 200 на любой ненайденный путь |
| Скрытые файлы | любой сегмент пути с точкой в начале — 404, кроме `/.well-known/` |
| Зарезервировано | `/_form/` и `/_dropsite/` принадлежат платформе |
| Кэш | HTML — `no-cache`, остальное — `public, max-age=3600` |

## Сертификаты и лимиты Let's Encrypt

По умолчанию каждый адрес получает свой сертификат при первом обращении (`TLS_MODE=ondemand`). Caddy запрашивает сертификат только для существующих адресов.

Let's Encrypt выдаёт **50 новых сертификатов на зарегистрированный домен за 7 дней** (на август 2026, см. [rate limits](https://letsencrypt.org/docs/rate-limits/)). Сайт со slug расходует два сертификата (случайный адрес и slug), то есть рассчитывайте примерно на **25 новых сайтов в неделю**. Продления в лимит не входят. При отказе Let's Encrypt Caddy переключается на ZeroSSL. Если этого мало, переходите в режим wildcard.

Каждый выпущенный сертификат попадает в публичные журналы Certificate Transparency, поэтому адреса сайтов не секретны.

**Режим wildcard** (`TLS_MODE=wildcard`) использует один сертификат на `*.<BASE_DOMAIN>` и корень, полученный через проверку DNS-01, поэтому новые сайты сертификатов не расходуют. Нужны DNS в Cloudflare (других провайдеров можно добавить) и API-токен с правом `Zone.DNS:Edit`:

```sh
# .env: CF_API_TOKEN=<токен>
docker compose -f docker-compose.yml -f compose.wildcard.yml up -d
```

В этом режиме у каждого релиза есть ещё и свой превью-адрес `https://p-<релиз>-<сайт>.<BASE_DOMAIN>/` (поисковики его не индексируют), он показан в истории релизов. Переход по шагам и откат: [docs/tls.md](docs/tls.md).

## Настройки

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `BASE_DOMAIN` | да | | Базовый домен сайтов |
| `ACME_EMAIL` | да | | Почта ACME-аккаунта |
| `ADMIN_EMAIL` | да | | Логин первого администратора |
| `ADMIN_PASSWORD` | да | | Его пароль; используется только при самом первом старте |
| `ADMIN_BIND_IP` | нет | `127.0.0.1` | Адрес, на котором слушает интерфейс |
| `UI_URL` | нет | `http://<ADMIN_BIND_IP>:8082` | Адрес в ссылках-приглашениях |
| `API_HOST` | нет | `api.<BASE_DOMAIN>` | Хост публичного API |
| `TLS_MODE` | нет | `ondemand` | `ondemand` или `wildcard`; wildcard задаёт `compose.wildcard.yml` |
| `CF_API_TOKEN` | только для wildcard | — | Токен Cloudflare с правом `Zone.DNS:Edit`, передаётся только Caddy |
| `MAX_SITE_BYTES`, `MAX_FILE_BYTES`, `MAX_FILES`, `MAX_SITES_PER_USER`, `KEEP_RELEASES` | нет | 50 МБ, 20 МБ, 2000, 10, 5 | Лимиты; администратор может переопределить их в интерфейсе |
| `RESERVED_SLUGS` | нет | | Дополнительные запрещённые slug через запятую |
| `LOG_LEVEL` | нет | `info` | `debug`, `info`, `warn`, `error` |

## Эксплуатация

- **Бэкап:** `docker compose exec -T control /control backup - > backup-$(date +%F).tar.gz`. Восстановление — в [docs/backup.md](docs/backup.md).
- **Обновление:** сделайте бэкап, затем `docker compose pull && docker compose up -d`. Миграции применяются автоматически, откат схемы не поддерживается.
- **Логи:** JSON в stdout обоих контейнеров: `docker compose logs -f`.
- **Здоровье:** `docker compose ps` показывает проверку здоровья `control`.

Подробнее: [docs/install.md](docs/install.md), [docs/backup.md](docs/backup.md), [docs/tls.md](docs/tls.md), [docs/production-checklist.md](docs/production-checklist.md).

## Модель безопасности

- Веб-интерфейс работает на отдельном listener-е, недоступном из интернета; cookie сессии привязана только к хосту интерфейса.
- API принимает только Bearer-токены, cookies не принимаются. Токен показывается один раз, хранится в виде хэша, может истекать и отзываться.
- Чужой сайт всегда отвечает «не найдено».
- Архив проверяется до записи на диск: никаких выходов за пределы каталога, ссылок, устройств и zip-бомб.
- Caddy видит том сайтов только на чтение и не имеет доступа к базе и токенам. Оба контейнера работают не от root с корневой файловой системой только для чтения.

## Разработка

```bash
make tools        # Go и golangci-lint в .tools/ (ничего не ставится в систему)
make test lint
scripts/dev-control.sh   # control без Docker, интерфейс на http://127.0.0.1:18082
make dev-up       # весь стек в Docker с локальным CA: https://<site>.dropsite.localhost:18443
make e2e
```
